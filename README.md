# RunnerGo 配送

一个可直接在本机运行的同城配送调度 MVP。项目从空仓库开始原创实现，不包含快跑者源码、商标素材，也不保存用户提供的线上系统凭据。

当前版本覆盖管理员、商户、骑手三种角色的真实业务闭环：

```text
商户/管理员发单 -> 商户余额扣款 -> 管理员派单
-> 骑手接单 -> 取货 -> 送达 -> 骑手收入入账
-> 订单事件、商户流水和骑手流水可追溯
```

## 已实现

- 管理员、商户、骑手登录和资源级权限隔离。
- 运营首页、订单管理、人工调度、商户、骑手、计价、流水、设置。
- 商户端发单、订单追踪、余额和费用明细。
- 响应式骑手端任务、接单、取货、送达、收入与工作状态。
- 状态机：`pending -> assigned -> accepted -> picked_up -> delivered`，另有取货前撤销。
- 商户扣款/退款、骑手入账和管理员资金调整；金额以整数分存储。
- `Idempotency-Key` 防止建单重试造成重复订单和重复扣款。
- 结算幂等、订单事件审计、账号停用后立即撤销全部会话。
- SQLite 本地数据、中文演示数据、14 项 API 集成测试。
- Vite 开发代理和单进程生产预览；无需 Docker 或外部服务。

## 快速开始

要求 Node.js `20.19+`、`22.12+` 或更新的受支持版本。

```powershell
npm install
npm run dev
```

开发页面：`http://127.0.0.1:5173`  
本地 API：`http://127.0.0.1:3000`

也可以构建后由一个本地进程同时提供页面和 API：

```powershell
npm run build
npm start
```

构建后的页面：`http://127.0.0.1:3000`

首次启动会在 `data/runner-deliver.db` 创建 SQLite 数据库并写入演示数据。配置可从 [.env.example](./.env.example) 复制到本地 `.env`；`.env` 和数据库均已加入忽略列表。

## 当前边界

本版本刻意不包含生产部署和需要线上资质/密钥的集成：真实地图、短信、微信/支付宝支付、自动打款、打印机、美团/饿了么授权、原生 App、AI 智能派单、校园中转和商品迁移。调度页使用本地模拟地图；相关能力应在确认合同范围与供应商后通过适配层接入。

新增商户或骑手目前只创建业务主体，不自动生成登录账号；正式项目应补管理员邀请、首次设密和密码重置流程。数据库适合全新本地实例，后续进入多人开发或生产前应增加版本化迁移。
